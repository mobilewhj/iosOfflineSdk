# Android 与 iOS 核心边界

两端保持相同的包管理和更新语义；页面资源交付根据 WebView 能力实现。iOS 离线页面使用 `loadFileURL`，不注册自定义协议。

## 包与 URL 规则

| 边界 | 规则 |
| --- | --- |
| HTTP/HTTPS 静态根 | 同域同路径，接受有效端口相同，或各为对应协议默认端口；未命中时保留原始 URL |
| minimumVersion | 约束新配置和候选；已有 active 不因门槛提高而被淘汰，仍检查文件资格 |
| 未知扩展名 | 合法且可读的文件允许使用，MIME 兜底 `application/octet-stream` |
| 包下载 URL fragment | 不作为非法配置，由网络栈处理 |

首次成功读库为空才首次准备；读库失败不当空库、不清理。无 active 时安装成功可立即激活；已有 active 时新包 ready 等下次冷启。配置失败、非法配置或同版 SHA 冲突保留先前策略。

页面选择不请求配置；未知策略可用 active，已知策略须版本/SHA 匹配；不降级、不原地重装损坏 active。更新请求开始间隔至少 300 秒，同目标非网络处理失败最多两次。后台停止新调度，不打断已进入准备的静默任务；撤回隐私、关闭和首装 owner 取消透传到底层。

ready 收尾已成立的成功不改写为取消失败。资源缓存清理不清 Cookie/localStorage。安装统计不从资源请求或一般诊断补造。宿主配置适配应区分非法候选和 SDK 显式无候选，不能用缺失字段伪造关闭或成功。

## WebView 差异

- Android 的 HTTP(S) 资源拦截可保留原 URL，未返回本地响应时继续网络加载。iOS file 页的相对资源为本地文件 URL，仅在入口未命中时回原地址；已加载本地页缺子资源不会逐资源回源。
- iOS file 页已获得的版本目录 read access 不随离线开关撤销。新页受最新策略约束，旧页保留原目录，直到宿主关闭。
- iOS 文件读取权限限定所选版本目录；身份和导航授权由宿主限定主文档。文件网络配置、HTTP(S) API 地址、Cookie 与存储行为按实际 WebKit 环境验证。

这些规则说明 SDK 合同，不代表任何宿主、账号、后端或物理设备的集成验收。具体接入见 [托管接入](MANAGED-INTEGRATION.md) 和 [文件页面](FILE-LOADING.md)。
